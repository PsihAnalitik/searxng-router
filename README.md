# SearXNG с бесплатным поиском и платным резервом

Сборка SearXNG для браузера и AI-агентов: бесплатные поисковики,
11 тематических пакетов и платный поиск через Tavily, Yandex Search API или Google CSE,
если бесплатный поиск не дал пригодных ссылок.

**Без API-ключей работает только бесплатный поиск.** Для запуска регистрация
у платных провайдеров не нужна.

Сам SearXNG загружается как Docker-образ; его исходников здесь нет.
В репозитории — конфигурация, скрипты запуска и наш роутер:

- `core` — SearXNG с веб-интерфейсом и обычным API;
- `backend` — второй SearXNG для тематических пакетов;
- `router/app.py` — переход к платному поиску, фильтрация источников и учёт попыток;
- `valkey` — хранилище счётчиков;
- `init` — генерация конфигов при запуске.

Сервисы описаны в [docker-compose.yml](docker-compose.yml).

## Запуск

Нужны Git, Docker Engine / Docker Desktop и Docker Compose v2.20+.
Python на хосте не нужен. На первом запуске Docker скачает образы.

```bash
git clone <URL-этого-репозитория>
cd <каталог-репозитория>
cp .env.example .env
chmod 600 .env
docker compose up -d --build --wait
```

- Веб-интерфейс и обычный SearXNG API: **http://127.0.0.1:8080**.
- API с бесплатным ярусом и опциональным платным резервом: **http://127.0.0.1:8090**.

Сервис `init` автоматически создаёт конфиги, доменные пакеты и внутренний секрет.
Его состояние `Exited (0)` нормально. Данные находятся в Docker volumes;
рабочие файлы репозитория и `.env` не перезаписываются.

```bash
curl -fsS http://127.0.0.1:8090/health
curl -fsS --get http://127.0.0.1:8090/search --data-urlencode 'q=Python документация'
# Обычный SearXNG, без платного резерва:
curl -fsS --get http://127.0.0.1:8080/search --data-urlencode 'q=Python' -d format=json
```

Без ключей `/health` возвращает `"paid": []`.

## Подключение Tavily

Получите собственный ключ в [Tavily](https://app.tavily.com/) и заполните `.env`:

```dotenv
TAVILY_API_KEY=<ваш-ключ>
TAVILY_TIMEOUT=5
PAID_ENGINES=auto
LIMIT_TAVILY_MONTH=1000
LIMIT_TAVILY_DAY=50
```

Лимиты ограничивают число **попыток** в день и месяц. Задайте их с учётом
квоты своего аккаунта; подробнее — [учёт попыток](#выбор-ключей-и-учёт-попыток).

После изменения `.env` или шаблонов:

```bash
docker compose up -d --build --force-recreate --wait
```

Платные ключи получает только роутер на порту 8090. В SearXNG на 8080
платные API недоступны, в том числе через банги — команды выбора движка.
Старый банг `!tv` удалён.

Для отключения удалите значение ключа либо установите `PAID_ENGINES=` и
пересоздайте сервисы той же командой. Пустой `PAID_ENGINES` отключает все платные вызовы.

Дополнительный ключ подключается только через `.env`, без редактирования YAML:

```dotenv
TAVILY_API_KEY_2=<другой-ключ>
LIMIT_TAVILY_2_MONTH=1000
LIMIT_TAVILY_2_DAY=20
```

Запросы отправляются как JSON, включая кавычки и кириллицу. Используются
`search_depth=basic`, `auto_parameters=false`, для пакетов и общего белого списка — `include_domains`.
Документация: [Tavily Search API](https://docs.tavily.com/documentation/api-reference/endpoint/search).

## Подключение платного Yandex Search API

Бесплатный движок `yandex` в SearXNG и платный `yandex-api` в роутере — разные
интеграции. Для платного поиска нужны API-ключ сервисного аккаунта с правом использования
Search API и folder ID — идентификатор каталога. Документация: [Search API v2](https://yandex.cloud/en/docs/search-api/api-ref/WebSearch/search),
[авторизация Api-Key](https://yandex.cloud/en/docs/iam/concepts/authorization/api-key).

```dotenv
YANDEX_API_KEY=<ваш-ключ>
YANDEX_FOLDER_ID=<folder-id>
YANDEX_TIMEOUT=3
LIMIT_YANDEX_API_MONTH=1000
LIMIT_YANDEX_API_DAY=50
PAID_ENGINES=auto
```

Для второго ключа: `YANDEX_API_KEY_2`, необязательный `YANDEX_FOLDER_ID_2`
(иначе используется общий folder ID), `LIMIT_YANDEX_API_2_MONTH/DAY`.
Ключ без folder ID не даст роутеру запуститься; без ключа интеграция отключена. После изменения примените команду
пересоздания Compose из раздела Tavily.

Yandex вызывается синхронно через `/v2/web/search`; XML из Base64 `rawData`
преобразуется в общий формат ссылок. XML-код 15 означает пустую выдачу, остальные
ошибки (в том числе 32/55 — ограничения) переводят поиск к следующему ключу.
Для `language=en...` используется `SEARCH_TYPE_COM`, иначе `SEARCH_TYPE_RU`.
Для пакетов добавляются `site:`-условия; итоговый запрос не должен превышать 400
символов. Ограничения API и запросов отражаются в `warnings`, а резерв попытки
сохраняется так же, как у Tavily.

## Подключение Google CSE

Официальный Custom Search JSON API [закрыт для новых клиентов](https://developers.google.com/custom-search/v1/overview).
Существующим клиентам Google даёт срок до **1 января 2027 года** для перехода
на другой сервис. Адаптер предназначен для аккаунтов с действующим доступом.

В `.env` задайте ключ и идентификатор Programmable Search Engine:

```dotenv
GOOGLE_CSE_API_KEY=<ваш-ключ>
GOOGLE_CSE_CX=<идентификатор-поисковика>
GOOGLE_CSE_TIMEOUT=5
LIMIT_GOOGLE_CSE_MONTH=1000
LIMIT_GOOGLE_CSE_DAY=50
PAID_ENGINES=auto
```

Имя платного движка — `google-cse`. Для второго ключа: `GOOGLE_CSE_API_KEY_2`,
`LIMIT_GOOGLE_CSE_2_MONTH`, `LIMIT_GOOGLE_CSE_2_DAY` и необязательный
`GOOGLE_CSE_CX_2` (иначе используется общий `GOOGLE_CSE_CX`). Ключ без CX
не даст роутеру запуститься. Один CX без API-ключа платный поиск не включает.
После изменения `.env` пересоздайте сервисы командой из раздела Tavily.

Запрос к [Custom Search JSON API](https://developers.google.com/custom-search/v1/reference/rest/v1/cse/list)
получает до 10 ссылок; `language` передаётся как `hl`, домены — через `site:`.
Ответ проходит тот же белый список и учёт попыток, что и другие провайдеры.
HTTP 403/429, ошибки API и пустая выдача переводят поиск к следующему ключу.
Бесплатный `google` в SearXNG работает отдельно от этого адаптера.

## API для агентов

Основной адрес: `http://127.0.0.1:8090/search`.

| Параметр | Значение |
|---|---|
| `q` | Обязательный поисковый запрос |
| `pack` | Необязательное имя тематического пакета |
| `limit` | 1–50, по умолчанию 5; ограничивает выдачу, не гарантирует её размер |
| `language` | Язык бесплатного SearXNG поиска; пакет задаёт свой язык в шаблоне |

```bash
curl -fsS --get http://127.0.0.1:8090/search \
  --data-urlencode 'q=epistemology' -d pack=philosophy -d limit=3
curl -fsS http://127.0.0.1:8090/budget
```

Ответ содержит поля `query`, `pack`, `tier`, `escalated`, `engines_used`,
`answers`, `results`, `warnings`. `tier` — `free`, `paid` или `none`.
`escalated` означает, что была предпринята платная попытка.
`engines_used` при бесплатном поиске перечисляет запрошенные движки; часть из них
может не ответить.

```json
{
  "query": "Python", "pack": null,
  "tier": "free", "escalated": false,
  "engines_used": ["google", "yandex", "bing", "duckduckgo web"],
  "answers": [],
  "results": [{"url": "https://www.python.org/", "title": "Python", "content": "...", "engine": "google"}],
  "warnings": []
}
```

При `tier=none` проверяйте `warnings`: там отражаются пустая выдача, отключённый
резерв, исчерпание бюджета и сбои. HTTP 400 — неверный запрос или пакет;
HTTP 502 — внутренняя ошибка. `/health` проверяет процесс роутера, а не доступность
внешних поисковиков. Для состояния сервисов используйте `docker compose ps`.

В Docker подключите агента к сети `searxng_default`; адрес роутера —
`http://router:8090`. При другом имени Compose-проекта изменится и имя сети.
Веб-интерфейс SearXNG остаётся доступен внутри сети как `http://core:8080`.
Старые имена `searxng-core`, `searxng-backend`, `searxng-router` сохранены как сетевые псевдонимы.

## Тематические пакеты

| `pack` | Банг в веб-интерфейсе | Источники |
|---|---|---|
| `dev sites` | `!dev` | Habr, Python Docs, Arch Wiki, MDN |
| `pogoda` | `!pog` | gismeteo.ru |
| `msk transport` | `!msk` | mos.ru, mosmetro.ru, ictransport.ru |
| `ru politics` | `!rupol` | Российские СМИ и государственные сайты |
| `tadviser` | `!tadv` | tadviser.ru |
| `ru geo` | `!rugeo` | РГО, Росстат, русская Wikipedia |
| `world data` | `!world` | Numbeo, World Bank, Macrotrends, Our World in Data |
| `reddit` | `!rdt` | reddit.com |
| `philosophy` | `!phil` | Stanford Encyclopedia, IEP, ИФ РАН |
| `ru science` | `!rusci` | КиберЛенинка, eLIBRARY |
| `education` | `!edu` | Образовательные сайты |

Домены и язык пакетов задаются в `core-config/settings.template.yml`.
Генератор извлекает из него фильтры роутера. `router/packs.json` — снимок для
локальных тестов; Compose использует копию, созданную при запуске в томе `runtime-config`.
Бесплатные запросы пакетов обрабатывает отдельный `backend`, чтобы исключить рекурсию.

Необязательный `GOOGLE_CSE_CX` подключает ваш Programmable Search Engine и
добавляет его к пакетам. Без него пакеты используют бесплатные Google/Yandex
(пакет Reddit — Google). В сборке нет чужого идентификатора CSE.

## Настройки

В `.env.example` перечислены основные параметры:

- `SEARXNG_HOST`: по умолчанию `127.0.0.1`; порты доступны только локально.
- `SEARXNG_PORT`, `ROUTER_PORT`: порты хоста; внутренние порты всегда 8080/8090.
- `SEARXNG_SECRET`: необязательный собственный секрет вместо автоматически созданного.
- `METRICS_PASSWORD`: необязательный пароль защищённых метрик SearXNG.
- `FREE_ENGINES`: бесплатный пул роутера.
- `PAID_ENGINES`, `TAVILY_API_KEY*`, `LIMIT_TAVILY*_DAY/MONTH`: платный резерв.
- `ALLOWED_DOMAINS`: белый список доменов, описанный ниже.

## Фильтрация источников и переход к платному поиску

В `.env` можно задать допустимые источники:

```dotenv
ALLOWED_DOMAINS=python.org,habr.com
```

Указывайте домены без схемы, пути и `*`; поддомены также разрешены.
Пустое значение отключает общий фильтр, неверный формат останавливает запуск
роутера. При выборе тематического пакета ссылка должна пройти оба фильтра:
общий список и список доменов пакета.

Хотя бы одна HTTP(S)-ссылка, прошедшая фильтры, завершает поиск.
Если её дал бесплатный движок, платных вызовов не будет.
Ошибки сети/HTTP/JSON, некорректная структура ответа, один текстовый `answers`
без ссылок и выдача целиком вне разрешённых доменов приводят к платному резерву
при наличии ключей и бюджета. Частичные ошибки движков остаются в `warnings`.
Платная выдача проходит тот же фильтр: запрещённые ссылки агенту не возвращаются.
При включённом фильтре `answers` пуст, поскольку у этого текста нет проверяемого
источника. Фильтр проверяет hostname выданного URL, а не релевантность содержимого
или адрес назначения после перенаправления. На прямой API и веб-интерфейс SearXNG (порт 8080) этот фильтр не действует.

## Таймауты платных запросов

Время одной попытки задаётся в `.env` в секундах:

```dotenv
TAVILY_TIMEOUT=5
YANDEX_TIMEOUT=3
GOOGLE_CSE_TIMEOUT=5
```

Это значения из `.env.example`; в коде значений по умолчанию нет.
Для каждого включённого провайдера таймаут обязателен. Отсутствующее, пустое,
неположительное или бесконечное значение вызывает ошибку при старте.
При обновлении существующей установки добавьте нужные переменные в `.env`.

Предел действует на DNS, соединение и чтение всего ответа. Платный HTTP-запрос
выполняется в отдельном процессе, который роутер завершает по истечении срока.
Зависший или медленно поступающий ответ не оставляет работающий фоновый запрос.
Попытка остаётся в счётчике, в `warnings` появляется таймаут, поиск переходит
к следующему ключу. Квота провайдера может быть потрачена даже после отмены клиента.

Это предел **одной платной попытки**, не всего поиска: время бесплатного этапа
и последовательных попыток складывается. Бесплатный запрос к SearXNG использует
отдельный `UPSTREAM_TIMEOUT` (таймаут сокета, по умолчанию 45 секунд).

## Выбор ключей и учёт попыток

`PAID_ENGINES=auto` включает все интеграции с непустыми ключами, в том числе
`TAVILY_API_KEY` и `TAVILY_API_KEY_2`. Чтобы выбрать ключи вручную, укажите,
например, `PAID_ENGINES=tavily,tavily-2,yandex-api,google-cse`.
Ключи без значения пропускаются; неверный ключ даст предупреждение при вызове.
Одинаковый ключ под разными именами запрещён.

Первым используется ключ с наибольшим остатком месячного лимита.
При равных остатках действует порядок в `PAID_ENGINES`.
Ключ с исчерпанным дневным или месячным лимитом пропускается без запроса.
При отказе провайдера по квоте роутер пробует следующий ключ в том же поиске.
Отказавший ключ может использоваться при следующем поиске, пока его локальный
лимит не исчерпан: например, HTTP 429 бывает временным ограничением частоты.

Разные ключи одного аккаунта могут делить общую квоту. Смена ключа её
не увеличивает; распределите локальные лимиты между ключами самостоятельно.

Роутер увеличивает счётчик **до** обращения к платному API. Проверка лимита
и увеличение счётчика выполняются атомарно: параллельные запросы не могут
превысить локальный лимит. Ошибки, пустые ответы и таймауты также занимают
попытку: при обрыве связи нельзя доказать, что поставщик не обработал запрос.
Автоматического повтора того же платного вызова нет. При недоступном Valkey платные вызовы
блокируются; бесплатный поиск работает независимо от него.

Счётчики `budget:<engine>:<месяц|день>` сохраняются в `valkey-data`, периоды
определяются датой контейнера (по умолчанию UTC). Плановый рестарт сохраняет данные;
аварийное завершение может потерять изменения после последнего снимка Valkey
(`--save 30 1`). Локальный счётчик не заменяет биллинг Tavily и не учитывает вызовы
этого ключа из других приложений. Удаление тома обнуляет историю лимитов.

`python3 scripts/tavily-usage.py` сопоставляет локальные попытки и данные аккаунта;
скрипт обращается к Tavily `/usage` с ключами из `.env`.

## Обновление и диагностика

```bash
docker compose ps
docker compose logs --tail=100 init core backend router valkey
git pull
docker compose up -d --build --force-recreate --wait
# Остановить без удаления томов:
docker compose down
```

Версии образов закреплены по digest (хешу содержимого) в Compose и Dockerfile. `SEARXNG_VERSION` позволяет
явно выбрать другую версию; перед обновлением проверьте её совместимость.
Не используйте `down -v`, если хотите сохранить секрет и бюджет.

При переходе со старой версии сохраните `.env` и прежнее имя Compose-проекта
`searxng`: существующий `valkey-data` и имена бюджетных ключей используются дальше.
Старый `core-config/settings.yml` больше не монтируется и остаётся нетронутым.
`backend-config/settings.yml` остаётся валидным бесплатным конфигом для старых
bind-mount установок; новый генератор читает `backend-config/settings.template.yml`.
Перенесите ручные правки в шаблон; удалите `SEARXNG_VERSION=latest` из старого `.env`,
если хотите использовать закреплённый образ. Для отката верните предыдущую версию
кода и Compose, сохранив `.env`, старый конфиг и тома. Схема счётчиков не меняется.

Движки могут отвечать CAPTCHA, ограничивать частоту или быть недоступны из вашей
сети. Работа движка в одной сети не гарантирует его доступности в другой.
Непустой `unresponsive_engines` в обычном SearXNG API не означает отказ всего поиска.
Сервер рассчитан на локальный доступ: изменение адреса на `0.0.0.0` открывает его
другим компьютерам, а авторизации роутера в этой сборке нет.

## Проверки и лицензия

```bash
python3 -B -m unittest discover -s tests -v
python3 tests/smoke.py
```

Unit-тесты подменяют внешние API. Smoke-тест поднимает отдельный Compose-проект
в Docker-сети без внешнего доступа, проверяет конфиги, HTTP API и атомарность
бюджета на реальном Valkey. Реальные ключи не используются; тестовые тома удаляются.
Docker может скачивать отсутствующие образы при сборке.

На живых запросах проверены Tavily, переход с бесплатного яруса на платный
и фильтрация разрешённых доменов. Переключение между ключами и адаптеры Yandex/Google
покрыты автоматическими тестами; живые проверки с двумя разными ключами
и ключами Yandex/Google не выполнялись. Жёсткий таймаут проверяется на локальном
HTTP-сервере с задержкой заголовков и побайтовой выдачей тела ответа.
